# SCUT 通知索引

主页入口卡片之后展示最新 8 条未读通知；`/scut` 展示所有已索引通知，可按来源、栏目、标题、未读状态筛选，每页 20 条。通知在新标签页打开官网，本站不保存正文或附件。

## 采集范围

- 学校主站：学术预告、教学科研通知。
- 数学学院：院务通知、本科生教务、研究生教务、科研通知、学工通知、学术报告、学院新闻、学院动态。合并首页和栏目分页，保留首页指向的外部通知链接。
- 本科生院：通知公告、学院通知下的信息、选课、考试、交流、实践、教师标签；无记录的标签显示为空，不认为它一定缺失。

仅访问固定的首页、栏目分页、公开列表接口及 robots.txt；不访问详情页、附件、微信公众号文章。抓取遵守 robots.txt；404/410 表示未提供规则，403、错误或明确禁止访问会显示失败。学校主站独立使用兼容旧密码套件的 TLS 上下文，仍校验证书和主机名。

## 自动更新与初始化

先运行 `uv sync --frozen`、`uv run python -m app.cli migrate`，再启动后端。新增三张索引表，不修改现有内容。`COPYLEE_SCUT_SYNC_ENABLED=true` 默认启用，与 GitHub 仓库同步开关互相独立。

后端启动后立即后台采集，之后按 10 分钟周期检查；前端在页面可见时每 60 秒读取本站 `/api/scut` 缓存。访问页面不会触发官网请求。每个域名单并发，两次请求启动至少间隔 2 秒，单请求超时 20 秒，最多重试两次。不重叠执行超过周期的任务。

首次保留近 365 天记录及日期未知的记录。每个栏目每轮补扫 5 个历史分页，位置持久保存，直到最后一页；不以某页日期较旧为停止条件，避免漏掉后面的乱序条目。初始化可能跨多个周期，页面显示完成栏目数量与已扫描/总页数。期间仍检查最新两页。初始化完成后，增量继续翻页到整页均为已知或超出首次索引范围；每天再分批复查全部公开列表，更新近一年新发现记录和已保留记录。历史通知不会因离开首页或超过一年被删除。

手动执行（需要没有其他 SCUT 采集进程正在运行）：

```bash
cd backend
uv run python -m app.cli sync-scut
# 加快首次补扫：每个栏目最多扫 100 页，仍按域名限速
uv run python -m app.cli sync-scut --pages-per-column 100
```

CLI 和服务共享数据目录下的跨进程锁；进程退出后操作系统释放锁，锁文件应保留。若服务已启用采集，通常无需手动同步。错误会使 CLI 返回非零退出码。每页持久保存，中断后重复执行可续传。

栏目失败保留旧索引、上次成功时间及扫描位置。官网结构变化、已有数据的栏目突然返回空列表、重定向或访问受限不会显示为成功。页面「刷新索引」只重新读取缓存，不强制抓取。采集状态是覆盖证据，不承诺官网不可访问期间索引实时完整。

## 浏览器阅读状态

键 `copylee.scut.reading.v1` 存储首访基准时间、显式已读和显式未读标记。收到首批非空索引后初始化：最近 7 天及日期未知的通知为未读，更早历史默认为已读；此后首次发现时间晚于首访时间的通知均为未读，即使其发布日期较旧。

点击标题、单条按钮、当前筛选全部已读都会保存状态；批量操作覆盖整个筛选结果，不局限当前页。同源的浏览器标签页同步标记，不跨设备同步。清除网站数据会重建首访基准。存储不可用时降级为内存状态并提示，通知仍可查阅。

## 部署与检查

前后端都需更新；迁移先于后端启动。Caddy 的 HTTP/HTTPS 示例新增 `/scut` 与 `/scut/` 静态入口，开发或 SSH 隧道直连 FastAPI 也能打开同一路径。已有数据库在线备份、恢复会包含 SCUT 表，无额外数据文件需要恢复。

本地验证：`npm run build`、`npm run test:scut`（Node 22.18+，或 Node 22.12+ 配合项目脚本的实验性类型剥离）、`cd backend && uv run pytest -q`、`uv run ruff check app tests migrations`。真实服务器还需核对三个域名出站访问、采集状态、周期运行，以及桌面/手机的筛选和阅读体验。本功能没有自动部署步骤。
